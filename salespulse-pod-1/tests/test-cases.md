# SalesPulse - Test Cases

CSV columns: `OrderID, OrderDate, ProductName, Category, Region, Quantity, UnitPrice, UnitCost`

Actual results and Pass/Fail are in [test-results.md](test-results.md) (generated by `python tests/run_tests.py`).

## Scenarios

| ID | Scenario | Input (OrderID, Product, Region, Qty, Price, Cost) | Expected behaviour |
|---|---|---|---|
| TC-01 | Normal valid order | `O1, Laptop, West, 2, 50000, 40000` | Valid. Revenue 100,000. Gross profit 20,000. AOV 100,000. |
| TC-02 | Zero quantity | `O2, Monitor, North, 0, 12000, 9000` | Invalid ("Zero or negative Quantity"). Excluded from all metrics. |
| TC-03 | Negative unit price | `O3, Office Chair, South, 3, -5000, 3000` | Invalid ("Zero or negative UnitPrice"). Excluded. |
| TC-04 | Missing product name | `O4, (blank), East, 1, 8000, 6000` | Invalid ("Missing Product Name"). Excluded. |
| TC-05 | Duplicate Order ID | Two rows with ID `O5` | Both rows invalid ("Duplicate Order ID", count 2). Neither counted. |
| TC-06 | Unit cost > unit price | `O6, Keyboard, South, 4, 3000, 3500` | Valid, not rejected. Revenue 12,000. Gross profit -2,000. Flagged as loss-making. |
| TC-07 | No valid orders | Only invalid rows | Valid orders 0, revenue 0, AOV 0 or N/A, no crash, report still generated. |

TC-02 to TC-05 are each run together with the valid TC-01 row, so revenue must stay at 100,000.

## Design decisions

- **Duplicate IDs:** every row sharing a duplicated Order ID is excluded, because we cannot tell which one is correct.
- **Loss-making orders:** kept, because they are real sales. They give negative profit and are flagged in the report.
- **Zero unit cost:** valid. Only negative costs are rejected.
